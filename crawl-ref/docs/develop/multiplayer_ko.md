# DCSS 협동 멀티플레이 설계

이 문서는 DCSS 0.34.1을 기반으로 한 서버 권위형 협동 모드의 기준이다.
프로토콜과 화면 문구보다 게임 규칙을 먼저 고정하여 서버와 클라이언트가
서로 다른 판정을 내리지 않게 하는 것이 목적이다.

## 현재 구현 상태

- 공식 DCSS 0.34.1 소스를 보존한 포크 기반
- 시간제한 턴, 자동 대기, 중복 명령 방지, 순환 우선순위 구현
- 동시 이동 충돌, 빈칸 연쇄 이동, 두 플레이어 위치 교환 구현
- 다운 및 관전자 전환 규칙 구현
- 파티 맵 이동의 집결, 자동 합류, 취소 판정 구현
- WebTiles 모바일 방향패드, 빠른 행동, 턴 표시줄, 정보 서랍 구현
- 한국어 설명 데이터 사용을 위한 `language = ko` 기본값 적용
- `USE_MULTIPLAYER` 빌드에서 활성 플레이어를 안전하게 교체하는 C++ 컨텍스트
  가드 구현
- 전용 WebTiles 서버의 공개 방 목록과 검증된 월드 설정 구현
- 대기방 플레이어 참가, 시작 후 난입 잠금, 시작 전후 관전 구현
- 방장 중심 WebRTC offer/answer/ICE 중계와 P2P 데이터 채널 구현

아직 C++ 게임 엔진은 전역 `you` 객체 한 명을 전제로 한다. 웹 서버의
조정기를 실제 공유 월드에 연결하려면 한 프로세스 안에 여러 플레이어
액터를 두는 엔진 작업이 추가로 필요하다. 여러 기존 게임 프로세스의
상태를 복제하는 방식은 RNG, 몬스터 AI, 아이템 상태가 어긋나므로 사용하지
않는다.

## 전용 서버와 P2P 방

전용 WebTiles 서버는 방 목록, 접속 ID, 방장, 설정, 참가 권한과 관전 권한의 최종
판정을 가진다. WebRTC 연결을 만들기 위한 offer, answer, ICE만 같은 방 사용자 사이에
중계하며 P2P 데이터 채널은 방장 브라우저와 각 참가자/관전자 브라우저가 직접 맺는다.
클라이언트가 보낸 대상 ID와 신호 종류는 서버에서 검증하며 64 KiB가 넘는 신호는
거부한다.

방 상태는 `waiting`과 `running` 두 가지다. 대기 중에는 빈자리가 있는 한 플레이어로
참가할 수 있다. 게임을 시작하는 순간 플레이어 명단을 잠그고 이후 접속은 관전자만
허용한다. 대기 중 방장이 나가면 가장 먼저 입장한 플레이어에게 방장을 넘기고, 실행
중 방장이 나가면 호스트 권위 월드를 종료한다. 각 방은 별도 저장 디렉터리를 사용한다.

월드 기본값은 원본 일반 DCSS와 무작위 시드다. 방장은 일반/지정 시드/디센트/스프린트,
2~8명, 3~60초 턴 제한, 3~60초 맵 이동 대기를 지정할 수 있다. 인터넷 운영 시에는
HTTPS와 방화벽이 필요하고, 대칭 NAT 사용자를 지원하려면 별도 TURN 서버가 필요하다.

## C++ 공유 월드 경계

`multiplayer-room.h/.cc`는 네트워크 계정 문자열과 엔진 actor ID를 분리한다. 방에
입장한 순서대로 1~8의 방 내부 `player_id`를 부여하고, 이 값으로 충돌하지 않는
`mid_t`를 만든다. 기존 코드가 `you`를 참조해도 `scoped_player_turn` 안에서는 선택된
플레이어를 가리킨다.

시야 자체는 각 `player`의 위치에서 계산한다. 기억해야 하는 정보는 기존 전역
`env.map_knowledge`, `env.map_seen`, `env.map_forgotten`, `env.visible`, 이동 흔적을
플레이어별 스냅샷으로 보관한다. 행동과 화면 동기화는 반드시 해당 플레이어 범위에서
실행해야 다른 사람의 탐험 지도가 새지 않는다.

C++ 턴 큐에는 서버가 확정한 `turn`, 방 내부 `player_id`, 원자 명령, `request_id`,
자동 대기 여부가 들어간다. 허용된 프로토콜 명령은 8방향 한 칸 이동, 대기, 줍기,
위층/아래층 이동이다. 저장, 매크로, 자동 탐색, 메뉴처럼 여러 입력이나 여러 턴을
소비할 수 있는 명령은 현재 원자 입력에서 거부한다.

WebTiles의 `RoomEngineBridge`가 브라우저 입력을 검증하고 다음 형태의 스키마 1 JSON을
공유 Crawl 프로세스 제어 소켓으로 보낼 수 있다.

```json
{"msg":"multiplayer_command_batch","schema":1,"turn":7,"reason":"timeout","commands":[{"player":1,"command":"move_left","request_id":"7:1","automatic":false,"payload":{"dx":-1,"dy":0}},{"player":2,"command":"wait","request_id":null,"automatic":true,"payload":{}}]}
```

현재 남은 가장 큰 엔진 작업은 이 묶음을 한 라운드로 실행하는 전용 루프다. 각
플레이어 명령 사이에는 몬스터 시간을 진행시키지 않고, 묶음이 끝난 뒤
`world_reacts()`를 한 번만 호출해야 한다. 또한 기존 코드가 공격 출처에 상수
`MID_PLAYER`를 저장하는 지점을 활성 플레이어의 고유 `mid`로 순차 변경해야 한다.

## 방과 턴

- 기본 인원은 2~4명이다.
- 방장은 턴 제한시간을 3~60초 사이에서 정한다. 기본값은 15초다.
- 행동 가능한 모든 플레이어가 제출하면 남은 시간을 기다리지 않고
  즉시 턴을 해결한다.
- 제한시간까지 제출하지 않은 플레이어의 행동은 `대기`가 된다.
- 두 턴 연속으로 행동하지 않으면 AFK가 되며 이후 턴 완료 조건에서
  제외된다. 돌아온 플레이어는 다음 열린 턴부터 복귀한다.
- 연결이 끊긴 플레이어는 즉시 자동 대기하므로 방을 멈추지 않는다.
- 클라이언트 명령에는 `turn`과 `request_id`를 붙인다. 같은 요청의 재전송은
  한 번만 처리하고, 한 턴에 서로 다른 두 행동을 보내면 두 번째를 거절한다.

### 해결 순서

1. 모든 플레이어 명령을 잠근다.
2. 직접 UI 명령처럼 시간이 들지 않는 행동을 처리한다.
3. 플레이어 이동과 공격을 순환 우선순위로 해결한다.
4. 투사체, 구름, 지속 효과를 처리한다.
5. 몬스터가 행동한다.
6. 환경과 상태이상의 시간이 흐른다.
7. 다음 입력 턴을 연다.

동일한 플레이어가 항상 먼저 움직이지 않도록 우선순위의 시작점은 매 턴
한 칸씩 회전한다. 서버만 최종 판정을 내리고 클라이언트는 결과를 예측
표시하는 역할만 한다.

DCSS의 행동 속도 체계는 전역 싱글플레이 턴에 깊게 연결되어 있다. 첫
공유 월드 버전에서는 시간이 드는 플레이어 행동을 10 aut 한 라운드로
정규화한다. 공유 월드가 안정된 뒤 원래 무기 속도와 가속 효과를 보존하는
에너지 큐를 추가한다. 메뉴 열기, 설명 보기, 목표 선택 취소는 턴을 쓰지
않는다.

## 이동과 전투 충돌

- 둘 이상이 같은 빈칸으로 이동하면 그 턴의 우선순위가 높은 한 명만
  이동하고 나머지는 제자리에서 대기한다.
- 앞 플레이어가 같은 턴에 비우는 칸으로 뒤 플레이어가 이동할 수 있다.
- 두 플레이어가 서로의 칸으로 이동하면 공격하지 않고 위치를 교환한다.
- 움직이지 않는 아군이 차지한 칸으로는 이동할 수 없다.
- 적이 있는 칸으로 이동하면 해당 적의 ID를 대상으로 근접 공격한다.
- 여러 플레이어가 같은 적을 공격할 수 있다. 앞선 공격으로 적이 죽으면
  남은 단일 대상 근접 공격은 자동 대기가 되며 소비 아이템은 쓰지 않는다.
- 첫 버전은 아군 직접 공격과 아군 대상 피해를 막는다. 범위 표시에는
  아군 위치를 강조하여 실수를 예방한다. 추후 방 설정으로 클래식 아군
  피해를 제공할 수 있다.
- 금화, 룬, 오브와 진행 열쇠는 파티 공유다. 장비와 소모품은 주운 플레이어
  소유이며 인접한 아군에게 한 턴을 사용해 건넬 수 있다.

## 다운과 부활

- HP가 0이 되면 즉시 사망하지 않고 3라운드 동안 `다운` 상태가 된다.
- 다운된 플레이어는 턴 완료 조건에서 제외되고 몬스터의 이동을 막지 않는다.
- 인접한 아군은 한 턴을 사용해 최대 HP의 30%로 구조할 수 있다.
- 구조 시간이 끝나면 해당 플레이어는 그 층에서 관전한다.
- 파티가 다음 층으로 이동하면 관전자는 최대 HP의 25%로 합류한다.
- 활동 가능한 플레이어가 모두 다운되면 즉시 파티 전멸이다.
- 별도의 클래식 방 설정에서는 다운 없이 원작 영구 사망을 사용할 수 있다.

## 맵 이동

일반 계단과 포탈은 파티 이동이며 첫 버전에서는 자유로운 층 분할을 막는다.

1. 플레이어가 계단을 사용하면 이동 요청과 10초 집결 시간이 시작된다.
2. 활동 중인 플레이어는 계단에서 기본 4칸 이내로 모여 준비를 누른다.
3. 모두 준비되면 현재 턴이 끝난 뒤 즉시 이동한다.
4. 시간이 끝났을 때 활동 플레이어가 모두 집결 범위 안이면 준비 여부와
   관계없이 함께 이동한다.
5. 멀리 있는 활동 플레이어가 있으면 이동 요청을 취소한다.
6. AFK, 연결 끊김, 다운, 관전 플레이어는 이동을 막지 않고 자동 합류한다.

함정 낙하, 추방, 어비스 이동처럼 게임이 강제하는 이동은 개인 이동을
허용한다. 강제 분리된 플레이어가 있는 동안에도 방 전체 턴은 하나이며,
플레이어가 있는 맵만 시뮬레이션한다. 파티 이동이 가능한 지점에서 다시
합류한다.

## 모바일 UX

- 화면 아래에 44px 이상의 8방향 패드와 대기 버튼을 둔다.
- 탐색, 줍기, 소지품, 능력, 주문, 취소, 위층, 아래층을 두 번의 탭 없이
  실행할 수 있다.
- 명령을 제출하면 다음 턴까지 행동 버튼을 잠가 빠른 연속 탭이 두 턴의
  명령으로 저장되지 않게 한다.
- 턴 번호, 남은 시간, 제출 상태를 항상 같은 위치에 표시한다.
- 세부 능력치와 몬스터 목록은 오른쪽 서랍으로 열어 작은 세로 화면에서도
  던전 영역을 확보한다.
- iPhone 노치와 홈 표시줄의 safe-area, Android 뒤로 가기, 가로 및 세로
  회전을 고려한다.
- 자동 탐색은 여러 키를 미리 쌓지 않고 매 라운드 한 단계씩 서버에 요청한다.
  새 적, 함정, 문, 아이템을 발견하면 즉시 멈춘다.
- 데스크톱 키보드와 마우스 입력은 기존 WebTiles 동작을 유지한다.

## 한국어화

원본에는 `dat/descript/ko` 아래에 몬스터, 신, 주문, 종족 등의 부분 번역이
이미 있다. `language = ko`는 번역이 존재하는 설명을 한국어로 표시하고
없는 항목은 영어로 안전하게 대체한다.

추가 멀티플레이 프로토콜은 완성된 문장 대신 `turn.timeout`,
`travel.player_too_far` 같은 메시지 키와 구조화된 값을 보낸다. 한국어
조사 처리는 클라이언트 문자열 계층에서 담당한다. 게임 로직에 한국어
문장을 직접 넣지 않아 영어 폴백과 향후 다른 언어를 유지한다.

## 엔진 연결 순서

1. 구현된 활성 플레이어 컨텍스트 위에 `player_id`를 가진 다중 플레이어
   컨테이너를 추가한다.
2. 입력 처리와 `world_reacts()` 사이를 수집 단계와 해결 단계로 분리한다.
3. 이동, 근접 공격, 계단부터 명시적인 플레이어 인자를 받게 바꾼다.
4. 서버 조정기의 확정 명령 묶음을 한 번에 C++ 프로세스로 전달한다.
5. 각 접속자에게 자신의 시야와 UI 데이터만 직렬화한다.
6. 아이템, 마법, 신앙, 자동 탐색 순으로 다중 플레이어 범위를 넓힌다.
7. 재접속 스냅샷, 저장 파일 버전, 악성 및 지연 패킷 테스트를 추가한다.

원본에는 `you.` 전역 접근이 약 14,000곳 있으므로 전체를 한 번에 치환하지
않는다. 먼저 이동과 기본 전투만 지원하는 수직 기능 조각을 완성하고,
나머지 기능은 서버에서 명시적으로 비활성화한 뒤 순차적으로 연다.
